- `autovacuum = on`, defaults (`scale_factor 0.2`, `threshold 50`, naptime 60 s). `track_counts = on`.
- Autovacuum/autoanalyze are running (last runs today on `source_revisions`, `domain_event_outbox`, …).
- No replication slots, no long-running / idle-in-transaction sessions holding back `xmin` → dead tuples can be removed.
- Dead tuple counts are tiny (max 53 rows). Small tables stay below the 50-row threshold, which is harmless.
- `source_revisions` is a hot counter (2968 updates on 27 rows) but 99.9 % HOT updates → cleaned by page pruning.
- XID age ~10.5 M, far from the 200 M freeze limit.

Conclusion: dead tuples are removed regularly by autovacuum; no tuning needed. Only real growth issue was the never-pruned outbox (#2).
