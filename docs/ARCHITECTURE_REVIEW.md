# Current architecture and consolidation review

Reviewed 30 September 2026 against [requirements](../REQUIREMENTS_ARCHITECTURE.md), [feature coverage](FEATURE_GAP_ANALYSIS.md), [implementation progress](IMPLEMENTATION_PROGRESS.md), and current source. This is a source/static review, not a new interactive UI audit or release sign-off.

## Assessment

F01–F23 have source implementations. The application has evolved into an operational modular monolith with stock, orders, custody, sourcing, maintenance, contributor work and reporting. The current problem is consistency of implementation boundaries and repeated mechanics, rather than the missing receiving/transfer/member workflows described in older reviews.

The frontend has useful reuse boundaries already: capability-specific resource APIs/hooks, CRUD dialog state, progressive lists, client pagination, operation forms, stock lookups, quantity conversion, media editing and order-detail sections. Preserve those boundaries and the existing Items/Assemblies/Storage foundation. The backend similarly has focused ORM classes and stock/custody services, but later additions bypass them.

### Additional removal

Removed `PositionService.ensureLegacy` and its runtime callers. Catalog creation now applies its initial stock transaction through the normal position command before persisting the ledger entry; reads, damage and transfers no longer synthesize positions from historical totals. No database was reset. Empty/disposable database behavior must be exercised in C09.

## Removal boundaries

The consolidated baseline is for empty disposable databases. Editing it changes its Flyway checksum; old databases must be recreated. No incremental upgrade, repair or backfill procedure remains. No database or browser storage was reset during this review.

Immutable transactions, order histories, sync failure/correction evidence, outbox recovery and report snapshots are active domain behavior. They are not dead code merely because they record old actions. Likewise, active browser fixtures and backend regression cases remain useful and were retained.

The existing graph was used for orientation and reports an older node-ID format; current source/reference checks underpin these findings. No full graph rebuild was performed, so it can still reference removed material.
