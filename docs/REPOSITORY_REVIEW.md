### R01 — MCP authorization and visibility (implemented in source)

**Original P1/high · SEC-01/02, CAT-05, C01/C03. Closed at the source level on 1 October 2026; runtime acceptance open.**

The reviewed implementation left `/mcp` outside the production `/api/*` rule and exposed catalog mutations, private items/components/custodians and global operational reads without an actor. OIDC dependency presence did not protect that route.

**Current evidence:** [application.properties](../backend/src/main/resources/application.properties) now protects exact `/mcp` and `/mcp/*` with an authenticated production HTTP policy. OIDC audience validation uses the configured backend client ID and protected resource metadata is enabled. The policy covers initialization, discovery, tools/resources/prompts and session requests. [ActorService.java:147](../backend/src/main/java/org/ash/inventory/helper/security/ActorService.java#L147) uses the shared Vert.x request for explicit development headers; the installed MCP extension sets that context and SecurityIdentity for Streamable HTTP and SSE invocations. No production actor-header authentication mechanism was added.

[McpInventoryService.java](../backend/src/main/java/org/ash/inventory/service/McpInventoryService.java) requires managers for item/assembly mutations and planners for event mutations. Item/asset/position reads use CatalogService visibility; assemblies use ApiQueryService's all-component visibility. Categories and event item maps use the same scoped ORM predicate. Summary/alerts include only visible active item pools; location and event metadata remain shared as in the catalog. Resources and prompts resolve the canonical actor. [InventoryMcpTools.java](../backend/src/main/java/org/ash/inventory/mcp/InventoryMcpTools.java) performs transport argument/error conversion and explicitly schedules database use cases on worker threads.

**Acceptance still required:** [InventoryMcpTest.java](../backend/src/test/java/org/ash/inventory/InventoryMcpTest.java) includes private item/asset/position/assembly/category/event reads, owner access, per-invocation role changes and caller attribution. These cases were authored, not executed. Verify production valid/expired/wrong-audience tokens, group/person/manager reads, SSE/session access and denial independently; the audience check also affects shared REST bearer validation. C09 remains open.

### R02 — MCP domain delegation and stock policy (implemented in source)

**Original P1/high · INV-01/02/04, AUD-01, C01/C04/C05. Closed at the source level on 1 October 2026; runtime/performance acceptance open.**

The reviewed MCP code maintained its own SKU, item/assembly/event CRUD, initial stock, pseudo-administrator and per-row queries. It omitted outbox publication, created invalid null-location positions, and calculated low-stock/position availability without canonical serialized, reservation, maintenance or equipment consent facts.

**Current evidence:** MCP tools/resources no longer inject EntityManager or execute queries. McpInventoryService delegates mutations to [CatalogService.java](../backend/src/main/java/org/ash/inventory/service/CatalogService.java), preserving locks, real-actor ledger ownership, media handling, tracking/amount guards, linked-event order checks and `catalog.changed` outbox publication. Create/update arguments use validated `ApiModels.ItemInput`, `AssemblyInput` and `EventInput`; catalog results use explicit `ApiResponses` records. Item deletion retires; the old permanent-delete and partial-patch contracts were removed. Serialized initialization creates assets without bulk positions; unlocated bulk uses the existing PositionService behavior.

Stock/alerts use [InventoryOperationsService.java:244](../backend/src/main/java/org/ash/inventory/service/InventoryOperationsService.java#L244), EquipmentReadService facts and canonical equipment policy. Position reads allocate command reservations with PositionService; shared PositionOrm readers now include remaining partially released reservations. They honor lot/damage/quarantine and contributor/maintenance/consent holds, and return no bulk positions for serialized items. Low-stock deficits use usable availability and clamp at zero. Maintenance alerts evaluate active calendar/hours/usage schedules with shared facts/counters, including unknown evidence. Assembly projections and stock fact loads batch datasets instead of querying each item/component count. Narrow category/status filtering stays in CatalogOrm; filters precede item/asset pagination. Domain failures leave the transaction before MCP tool error conversion.

**Acceptance still required:** The updated MCP regression source covers actual caller/outbox attribution, serialized/unlocated creation, invalid quantities/stock-edit rollback, purchase-linked event deletion, prepared/partially released reservations, contributor/availability holds and maintenance schedules. It was not compiled or run. Compare REST/MCP outputs for bulk/lot/serialized, faction/general reservations, contributor holds, restricted stock, maintenance and transit; verify connected SSE/ETag refresh. Measure SQL/row work before claiming speedup. Summary, low-stock and maintenance aggregate reads still scan the visible catalog, and event/assembly lists retain their shared catalog loading cost. No schema change was needed.

### R03 — Availability snapshots omit the contributor-damage hold

**P2/medium · high confidence · INV-02, F17/F20, C04.** Remaining availability-policy adoption gap; the schedule evaluator fix A05 is present.

**Evidence:** [EquipmentService.java:176](../backend/src/main/java/org/ash/inventory/service/EquipmentService.java#L176) returns zero for an unresolved contributor damage request. EquipmentReadService loads that fact, but [OperationalReportService.java:189](../backend/src/main/java/org/ash/inventory/service/OperationalReportService.java#L189) checks only freelyAvailable/itemUsable for bulk rows. The serialized `boolean available` expression likewise omits `hasMemberDamage`. `itemUsable()` covers maintenance, not the separate contributor hold.

**Trigger/impact:** Create an unresolved member damage request for otherwise usable organization stock, then rebuild availability. Catalog/planning/checkout exclude the pool; snapshot rows can show positive available units. This is misleading current-snapshot availability even without staleness; command validation still blocks checkout, so no bypass is claimed.

**Change:** Apply the shared whole-pool eligibility hold to both bulk and serialized location rows while retaining location FEFO/reservation allocation. Keep physical on-hand/damage and the contributor review request distinct; resolving a request must not create stock or auto-resolve a damage incident.

**Effort/risk/verification:** Small (<1 day), medium projection-parity risk. Rebuild before/after open/coordinating/resolved requests for bulk/lot/serialized; assert summed location availability agrees with the same unrestricted pool policy and command decisions, including active maintenance holds.

### R04 — Offline collection queries can pause before IndexedDB fallback runs

**P2/medium · high confidence · OFF-01/02, F16, C05.** U02 fixed exact detail coverage and detail scheduling; collection scheduling remains incomplete.

**Evidence:** [useProgressiveList.ts:13](../src/hooks/useProgressiveList.ts#L13) and [useResourceApi.ts:7](../src/hooks/useResourceApi.ts#L7) omit `networkMode`; session defaults set retries/staleTime only. Detail explicitly uses offlineFirst. [resourceFactory.ts:74](../src/services/resourceFactory.ts#L74) is inside the collection query function after a network failure. Installed TanStack Query's [retryer.ts:57](../node_modules/@tanstack/query-core/src/retryer.ts#L57) defaults unspecified mode to online and [retryer.ts:137](../node_modules/@tanstack/query-core/src/retryer.ts#L137) pauses before executing it. This dependency link is local inspection evidence, not a version-independent public contract.

**Trigger/impact:** With saved catalog pages but no in-memory query data, mount the collection after an offline event has set TanStack's online manager to false. This can happen during cold initialization or when a session generation replaces QueryClient while offline. Collection query functions then cannot run, so saved IndexedDB lists are unavailable or remain loading/paused. A downloaded item detail can now open via U02, but cached list selectors may remain empty. The installed online manager initially assumes true and changes on browser events ([onlineManager.ts:15](../node_modules/@tanstack/query-core/src/onlineManager.ts#L15)); therefore a cold launch without an offline event may execute fallback successfully. Neither every cold launch failing nor that success proving offline scheduling is claimed. Existing warm React Query data also masks the condition.

**Change:** Explicitly allow a first offline attempt for collection readers that have durable fallback. Give progressive cached collections an intentional offline mode and clear partial/unavailable-page UX; stop at the first unavailable page without claiming completeness. Preserve query/session namespaces and last-download timestamps. Do not globally make server-only operational readers run offline.

**Effort/risk/verification:** Small-to-medium (about 1 day), medium request/pagination risk. Cold-start online→offline with cached and uncached pages, filters and >100 items; confirm visible first/later pages, partial coverage, exact details, freshness and reconnect continuation. Exercise default online-only lists separately. A browser test must set/query the actual offline manager state, not just reject fetch.

### R05 — The shipped frontend server forbids camera scanning

**P2/medium · high confidence · F22, C09.** Deployment mismatch, outside A/P/U implementation scope.

**Evidence:** [Dockerfile:12](../Dockerfile#L12) installs the repository nginx configuration. [nginx.conf:11](../nginx.conf#L11) sends `camera=()` on responses. [CameraScanner.tsx:28](../src/components/shared/CameraScanner.tsx#L28) requests camera video. The camera permission policy governs this API and denial rejects the request: [camera directive reference](https://developer.mozilla.org/en-US/docs/Web/HTTP/Reference/Headers/Permissions-Policy/camera).

**Trigger/impact:** Use a secure deployed frontend served by this nginx configuration on a browser supporting BarcodeDetector. Camera is denied by policy before normal user permission can enable it. Manual/handheld-code entry remains usable, but source-only camera checks or the Vite dev server miss the deployed failure.

**Change:** Allow camera for the application's own origin while preserving unrelated feature restrictions; confirm any reverse proxy/embedding policy permits the same intended scope. Retain unsupported-browser/manual fallback and stop tracks on hide/unmount/completion. No general permissions expansion is needed.

**Effort/risk/verification:** Small (<0.5 day), low configuration risk. Inspect actual HTTPS response headers and start/deny/stop scanning in the deployed container on supported desktop/mobile browsers, including route change/backgrounding. No deployed browser verification was performed here.

### R06 — Inbox polling still performs one usage-counter query per eligible schedule

**P2/medium performance · high confidence for query fan-out; latency unmeasured · F21, C04/C09.** Shared maintenance semantics are fixed; batching adoption is incomplete for this reader.

**Evidence:** [ActionInboxService.java:57](../backend/src/main/java/org/ash/inventory/service/ActionInboxService.java#L57) loops through schedules and calls live evaluator status. [MaintenanceEvaluationService.java:20](../backend/src/main/java/org/ash/inventory/service/MaintenanceEvaluationService.java#L20) issues a checkout aggregate for each usage-count schedule. [ActionInboxOrm.java:39](../backend/src/main/java/org/ash/inventory/orm/ActionInboxOrm.java#L39) loads all active schedules before role/responsible-person filtering. [useActionInbox.ts:7](../src/hooks/useActionInbox.ts#L7) repeats this reader each minute while active. Multiple eligible schedules for one item/asset repeat the same count.

## 8. Operational semantics that must survive further work

**Stock/custody:** Physical on-hand, custody, reservations, transit and ownership are separate. Serialized pending-check assets remain checked out. Owned stock retains organization transit; external purchase quantities are ordered supply until receipt, not owned stock. Damage repair changes condition, not quantity. Write-off explicitly changes owned stock. Missing remains a subset of outstanding; never subtract it twice. Order reconciliation satisfies handedOver = returned + consumed + damaged + writtenOff + outstanding, with missing ≤ outstanding. Cached quantities/reports never authorize a command.

**Orders/planning:** Requests may exceed stock. Preparation validates source stock and exact assets under locks; pickup converts reservations to custody atomically. Editing credits only that order's reservation. Reopen/cancel release reservations without inventing stock/location changes. Assembly quantities normalize to component demand while preserving source assembly history. Faction reservations and general prepared maps differ intentionally. Planning compares active request demand with unfulfilled total forecast, accumulates consumable demand and considers reusable overlap/return-readiness. Receipt dates and owner consent are separate supply constraints; late/undated incoming still appears separately.

**Ownership/loans:** Visibility, owner, keeper, physical location and custodian are independent. One pool has one owner; commitment windows, return dates, exact assets, revisions and conservative idle checks constrain lending. Private/external supply requires consent; purchasing alone cannot grant it. Loan agreements precede physical transfer. Collection/return evidence links completed discrepancy-free transfers in the correct direction exactly once, with quantity/identity caps. Only collected, unreturned internal equipment supplies events. Physical provider return before evidence cannot silently remain eligible. Extensions require reason/revision/overlap checks; cancellation after collection still needs physical return. Rental cost is evidence, not automatic stock.

**Contributor/inbox/scanning:** Keeper assignments use real accounts and exact locations, without automatic hierarchy inheritance. Personal custody/requests retain minimal evidence and stable command IDs; pending quantities remain bounded by outstanding custody. An unresolved contributor damage request blocks the pool without posting an automatic stock adjustment (R03 must reflect that in reports). Pickup requests coordinate, not move stock. SSE strips private request evidence. Inbox is live recipient-scoped work: minute refresh, reminders within 30 days, attributable overdue returns, earlier lot expiry/best-before and shared maintenance counters. Codes resolve exact targets; camera needs supported browser/secure deployment policy and track cleanup, with manual fallback. Alias retirement and immutable history are active behavior.

**Offline/recovery/reports:** Only individual stock, media-free damage and faction create/prepare/transition/reconciliation commands are queued. Catalog/general/member/media/assembly batch/equipment/loans/labels/purchasing/transfers/counts/lifecycle/reminders/report rebuilds require connectivity. Queued means stored locally, not applied. Durable queue/failure/history belongs to its original account; corrected terminal commands use a new ID, reason and correction root, with one applied chain. The service worker caches shell, not API responses. Item details fallback only for downloaded exact entries; filtered pages are not a complete catalog. Report snapshots are manually rebuilt/query-only, with generation/freshness/export semantics and bounded filtering cache. Outbox delivery remains at-least-once with leases/retry/dead-letter recovery; history is not obsolete code.
